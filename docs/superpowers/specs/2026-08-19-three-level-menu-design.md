# 三级菜单示例设计

## 目标

新增一组完整可见的三级菜单，用于验证路由配置、菜单层级、三级页面渲染、菜单高亮和面包屑是否协同工作。

## 菜单结构

```text
一级菜单
└── 二级菜单
    └── 三级菜单
```

三个路由节点都参与菜单显示，不设置 `showInMenu: false`。一级和二级路由作为菜单目录，三级路由作为可点击页面菜单。

## 路由与页面

新增路由路径：

```text
/level-one/level-two/level-three
```

新增简单页面：

```text
src/pages/level-one/level-two/level-three.tsx
```

三级页面仅渲染明确的测试文本，不新增接口、全局状态或业务逻辑。一级和二级路由是否配置 `element` 遵循现有路由配置约定，不由菜单派生逻辑强制处理；为保证三级路由可渲染，必要的父级页面布局应提供 `<Outlet />`。

## 配置约束

- 一级路由配置 `title: '一级菜单'` 和唯一 `menuKey`。
- 二级路由配置 `title: '二级菜单'` 和唯一 `menuKey`。
- 三级路由配置 `title: '三级菜单'` 和唯一 `menuKey`。
- 三个节点均不配置 `showInMenu: false`。
- 暂不配置权限限制。
- 菜单从路由树自动派生，不维护独立菜单数据。

## 验收标准

- 派生菜单包含一级、二级、三级的正确嵌套关系。
- 三级菜单出现在侧边菜单中并可点击。
- 访问 `/level-one/level-two/level-three` 后显示新建的简单页面。
- 当前三级菜单高亮，一级和二级菜单保持展开。
- 面包屑按“一级菜单 / 二级菜单 / 三级菜单”显示。
- 相关测试、TypeScript 检查和 lint 通过。
